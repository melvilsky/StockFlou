# StockFlow Design System

## Overview

Выбранное направление — **вариант 10, «Большая сетка — редактор на всю ширину снизу»**. Решение пользователя зафиксировано 29 октября 2026 года. Другие варианты из обсуждения не являются заданиями на реализацию.

**Creative North Star: «Графитовый рабочий стол фотографа».** Фотографии занимают основное пространство; интерфейс остаётся плотным, спокойным и хорошо читаемым. Матовые тёмные поверхности, слегка приподнятые кнопки, углублённые поля и светлый пыльно-синий акцент создают глубину без тяжёлого декора.

Это Flutter desktop, основная платформа приёмки — macOS. Существующее приложение и его бизнес-логика сохраняются. Название — StockFlow; основной язык UI — русский. Данные, имена и счётчики в макете демонстрационные.

**Key Characteristics:**

- Графитовая нейтральная основа, приглушённый синий для выделения и основных действий.
- Мягкая тактильность контролов при строгом выравнивании.
- Текстовые статусы вместе с иконкой, видимый клавиатурный фокус.
- Одинаковые формы кнопок, полей и карточек на всех экранах.

Порядок источников: требования пользователя и сохранность данных → поведенческий контракт проекта → [спецификация workspace](docs/design/variant-10/workspace-spec.md) → эталонная картинка → числовая калибровка при реализации. Семантика и доступность важнее случайных артефактов генерации изображения.

Эталон: [reference.png](docs/design/variant-10/reference.png). Целевые токены: [tokens.json](docs/design/variant-10/tokens.json). Задание следующему агенту: [stockflow-redesign-10.md](docs/agent-prompts/stockflow-redesign-10.md).

## Colors

Единый источник целевых значений — `docs/design/variant-10/tokens.json`. Внедрённые константы: `lib/core/theme/design_tokens.dart`; палитра и стили контролов: `lib/core/theme/app_theme.dart` (`AppPalette.dark` / `AppPalette.light`). Числа калибровались в работающем приложении, а не снимались с PNG пипеткой.

| Роль | Токен | Применение |
|---|---|---|
| Фон | canvas | Промежутки, основа workspace |
| Панель | surface | Верхние панели, карточки, редактор |
| Приподнятая поверхность | surfaceRaised | Кнопки, токены ключевых слов |
| Наведение | surfaceHover | Интерактивные поверхности |
| Углублённое поле | field | Search, title, description |
| Декоративный разделитель | border | Границы панелей, разделители |
| Граница контрола | controlBorder | Там, где граница необходима для распознавания поля |
| Текст | text / textMuted | Основной / второстепенный, без дополнительного ослабления opacity |
| Основное действие | primary / onPrimary | Светлая кнопка и тёмный текст |
| Выделение и фокус | selection / selectionSurface | Обводка и слабая заливка; обязательно дополнительные маркеры |
| Результат | success / warning / error | Подтверждённое состояние, предупреждение, ошибка |

**Правило акцента.** Синий обозначает выбор, фокус или действие. Он не окрашивает все поверхности. Зелёный не означает «готово», если операция ещё выполняется.

Тёмная палитра утверждена для первой реализации. Светлая тема отдельно не утверждена: сохранена существующая светлая палитра с прежним насыщенным акцентом (`#137FEC`), семантические роли перенесены в `AppPalette.light`. Системная тема по-прежнему управляет `ThemeMode.system`.

## Typography

Оставлен существующий **Inter** (`GoogleFonts.interTextTheme`), Instrument Sans из SL UI — только ориентир характера и не добавлялся. Шрифт не поставляется в ассетах: при первом запуске без сети `google_fonts` отдаёт системный fallback с кириллицей — это известное ограничение текущего проекта, а не следствие редизайна.

Размеры, веса и интерлиньяж — в `typography` токенов. Имя файла — label, обычные поля — body, размеры/формат/статус — caption, заголовки групп редактора — section. Не уменьшать важные подписи ниже caption ради плотности. Не использовать декоративные заглавные буквы и разрядку. Имена файлов допускают ellipsis и tooltip; вводимые метаданные не обрезать без доступа к полному тексту.

## Layout

Использовать ритм `spacing`, размеры — логические пиксели Flutter. Поверхности разделяются тонкой границей и интервалом, а не множеством вложенных карточек.

Конкретная композиция варианта 10 относится к workspace и описана отдельно. Для остальных экранов наследуются палитра, шрифт, формы и состояния; не заставлять настройки или историю повторять фотосетку. Не удалять функции только потому, что их не видно в кадре эталона.

Сохранять нативные системные области окна macOS, resize, полноэкранный режим и масштабирование текста. Размер макета — ориентир пропорций, не фиксированный размер окна.

## Elevation & Depth

Матовая поверхность: слабый верхний блик и короткая мягкая тень. Числовые параметры — `elevation`. Светлый primary может иметь едва заметный вертикальный переход `primaryTop → primaryBottom`; второстепенные кнопки графитовые. Изображения не затемнять декоративными фильтрами.

Hover меняет тон поверхности; press слегка углубляет кнопку без смещения всей компоновки. Фокус — отдельная контрастная обводка, не свечение. Времена — `motion`. Учитывать системное уменьшение анимации.

## Shapes

Радиусы по `radius`: панель крупнее контрола, карточка компактна. Обводка 1 логический пиксель, выделение и focus — 2. Контуры скруглений совпадают с clip изображения. Не превращать все элементы в капсулы. Маленький визуальный крестик чипа имеет увеличенную область нажатия.

## Components

Это целевые спецификации, не перечень уже внедрённых компонентов.

- **Primary button:** светлый пыльно-синий, тёмный текст, видимый disabled, busy с сохранением ширины, без повторного запуска. Главная кнопка редактора — сохранение/применение изменений, не автоматическая отправка.
- **Secondary / icon button:** графитовая поверхность, граница, читабельная иконка; tooltip и доступное имя обязательны. Фокус и hover различимы.
- **Поле ввода:** углублённый фон, постоянный label, focus-обводка, ошибка текстом под полем. Placeholder не заменяет label. Счётчики и ограничения берутся из правил приложения, а не чисел на PNG.
- **Чип ключевого слова:** компактный прямоугольник с мягким радиусом, отдельная кнопка удаления; клавиатурная навигация, сохранение существующего порядка и дедупликации.
- **Segmented control:** общий графитовый контейнер, выбранная вкладка светлая, переключение клавиатурой. Числа рассчитываются по текущей области поиска.
- **Media card:** фотография, filename, статус, размер/разрешение. Выделение — обводка плюс checkbox; фокус отдельно. Видео — существующий thumbnail, play и длительность при наличии данных. Ошибка/недоступность файла видимы.
- **Редактор:** общий нижний блок, группы «текст», «ключи и Editorial», «действия». Состояния 0/1/N файлов и правила применения — в workspace-spec.
- **Feedback:** успех после подтверждения операции; частичный результат показывает успешные и ошибочные файлы. Ошибку не скрывать одной цветной точкой.

Источник визуального языка: [SL UI Library](https://github.com/SLtowl/sl-ui-library), [use-sl-ui](https://github.com/SLtowl/sl-ui-library/blob/main/plugins/sl-ui-library/skills/use-sl-ui/SKILL.md). Код библиотеки в приложение не интегрирован. Для Flutter использовать существующие нативные виджеты и стилизацию; это визуальная адаптация, а не подтверждённая интеграция HTML/JS компонентов SL UI. Не добавлять WebView, React или новый пакет ради внешнего вида. При отдельном требовании именно интеграции SL UI соблюдать её source gate и аудит.

## Реализованные ограничения

- Двойной клик по карточке не открывает просмотр: двойной тап-распознаватель держал таймер и конфликтовал с одиночным выделением. Полный просмотр доступен из меню карточки (`more_horiz`) — это разрешено контрактом workspace.
- Панель поиска одна и живёт в глобальной верхней панели; в workspace второй строки поиска нет.
- Нижний редактор: `editorDefaultHeight` 248, минимум 224, рост перетаскиванием до `min(45% окна, высота области − gridMinVisibleHeight)`. При нехватке высоты (или 150% text scaling) он сворачивается в строку, а из неё открывается как sheet.
- Режимы нескольких файлов: по умолчанию ключи **добавляются** (индивидуальные сохраняются), полная замена — отдельный режим «Заменить». Editorial и AI-тег — tri-state («Не менять / Вкл / Выкл»).
- «В очередь» использует существующий `canBeQueuedForUpload`, активные стоки и `UploadProtocol.sftp` (как в экране загрузок); уже загруженные на сток файлы пропускаются с сообщением, мгновенная публикация не выполняется.
- QC в workspace выполняет существующий `QcChecker` по активным стокам и показывает существующий `QcReportDialog`; файлы без записи в БД сначала нужно сохранить.
- Светлая тема сохранена рабочей, но не проходила отдельную визуальную приёмку; первая приёмка — тёмная.
- Частичная ошибка batch-записи показывает диалог с успешными/ошибочными файлами; неприменённые правки остаются в форме для повтора.

## Do's and Don'ts

### Do

- Сохранять реальные данные, состояния, функции и совместимость проекта.
- Проверять размер окна, keyboard, focus, contrast, text scaling и ошибки.
- Выносить повторяемые значения в существующую тему; добавлять только необходимые небольшие компоненты.
- Считать выбранный PNG ориентиром компоновки и характера, а документ — контрактом поведения.

### Don't

- Не выдавать концепт за реализованный интерфейс.
- Не вводить неон, стекло, тяжёлые тени, маркетинговые панели и новые шрифты ради сходства.
- Не переносить демонстрационные счётчики, пути, лимиты и фото в рабочие данные.
- Не менять схемы БД, правила очереди и формат метаданных ради редизайна.
