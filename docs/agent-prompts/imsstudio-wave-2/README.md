Дата подготовки: 22 октября 2026 года.

Три задания можно запускать одновременно в трёх отдельных чатах. Каждый файл содержит полный самостоятельный промпт: контекст, разрешённые файлы, поведение, исключения, тесты и формат отчёта. Агенты этой группы ещё не запускались.

## Что показала проверка

Все 91 существующий тест прошли; flutter analyze сообщил No issues found. Интеграция записи/чтения/очистки описания через настоящий ExifTool также прошла.

Основная работа первой группы выполнена. В CSV воспроизведены проблемы с невозможной датой, конфликтом повторных строк и непустым Path из пробелов. По коду обнаружены перенос Editorial между инспекторами и отсутствие обновления filesProvider при закрытии частично успешного импорта.

Подробная приёмка: [проверка первой группы](../imsstudio-wave-1/REVIEW.md).

## Промпты для отдельных чатов

| Чат | Полный промпт | Результат | Основная зона изменений |
|---|---|---|---|
| 1 | [Безопасный контекст генерации](01-generation-context.md) | Выбор другого файла не подменяет Editorial и настройки запущенной генерации; поздние ответы безопасны | generation_screen.dart, собственная небольшая операция генерации, тесты generation_context |
| 2 | [Проверка и применение CSV](02-csv-edge-cases.md) | Строгая дата, исключение всех конфликтующих строк, точный Path, видимость частичного успеха | csv_metadata_service.dart, csv_import_plan.dart, CSV-диалог, тесты csv_metadata |
| 3 | [Сохранение рабочих папок](03-workspace-persistence.md) | Отключённый диск не теряет рабочую область; безопасная миграция настроек и состояние в боковой панели | workspaces_provider.dart, блок рабочих областей main.dart, собственные тесты |

Чаты 1 и 2 закрывают конкретные замечания проверки. Чат 3 делает следующий независимый шаг плана по рабочим папкам. Ни одному не требуется ждать изменения интерфейсов от другого.

## Как передать задания

Открой каждый промпт и скопируй его целиком в отдельный чат, работающий с /Volumes/orico/Projects/StockFlou. Не передавай только краткое описание из таблицы: границы и тесты находятся в полном тексте.

При работе в одной общей папке каждый агент меняет только свои перечисленные файлы. Им запрещены общий auto-fix/format, откат чужих правок, изменение зависимостей, коммиты и очистка рабочей директории.

Если чаты используют отдельные рабочие копии, каждая должна начинаться с одинакового актуального состояния, включающего выполненные изменения первой группы и её новые файлы. Сейчас часть этих файлов ещё не зафиксирована в Git: новая рабочая копия только от HEAD может их не содержать. Не начинай реализацию на устаревшей основе.

## Почему задачи независимы

- Существующий generation_screen.dart принадлежит только чату 1. Его публичный конструктор остаётся совместимым.
- Чат 2 обновляет наблюдаемый каталог из собственного диалога. Он сохраняет bool-контракт и не меняет родительский экран.
- Чат 3 сохраняет существующие getters и методы workspacesProvider. Генерация продолжает работать с тем же currentPath и refreshWorkspaceProvider.
- AppFile, DatabaseHelper, filesProvider, MetadataService и зависимости читаются, но не изменяются ни одним из трёх чатов.
- Новые вспомогательные файлы, тестовые папки и файлы отчёта у каждого свои.

Независимость зон не отменяет общую приёмку после объединения: приложение всё равно использует все три функции вместе.

## Общая приёмка после завершения

1. Прочитать 01-result.md, 02-result.md и 03-result.md; сверить реальный diff с разрешёнными зонами.
2. Выполнить полный flutter test и flutter analyze --no-pub после завершения всех трёх чатов. Не сравнивать промежуточный запуск, когда соседний чат ещё пишет файл, с итоговой приёмкой.
3. Проверить A → запуск генерации → выбор B → завершение A; B не получает данные A и A не получает Editorial B. AI-признак остаётся ручным.
4. Проверить CSV с повторными целями, невозможной датой, частичным отказом сохранения и закрытием диалога.
5. Проверить сохранение недоступной рабочей папки, перезапуск и повторное подключение; отдельно выполнить ручную проверку bookmarks на macOS, если она ещё не проводилась.
6. Повторно оценить следующие изменения общего каталога и черновиков.

## Что не запускать параллельно с этой группой

Общий каталог с постоянными id, миграцию модели AppFile, устойчивые черновики, ревизии метаданных и явную команду записи в оригиналы нужно выделить в следующий согласованный этап. Эти изменения пересекаются по базе, filesProvider и экрану генерации.

Также здесь не реализуются полноценное дерево каталогов, перемещение/переименование файлов, коллекции, менеджер security scopes для всех операций и новая очередь загрузки. Задание про рабочие папки исправляет сохранность списка и показывает доступность, но не решает эти большие задачи.
