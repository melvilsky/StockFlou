## Правила снимка контекста

1. **Момент фиксации:** снимок `MetadataGenerationContext` создаётся до первого `await` одиночной операции и до постановки задач в `Pool(3)` пакетной операции.
2. **Замораживаемые поля:** целевой `targetPath`, исходный `targetId` (при наличии в базе), текст `userContext`, API-ключ, количество ключевых слов, признак `isEditorial`, город, страна и дата.
3. **Локальность EXIF и геоданных:** результаты чтения метаданных и обратного геокодирования обогащают только локальный объект операции (`opContext.copyWith(...)`) и не вызывают мутаций `editorialNotifier` для других файлов.
4. **Актуальные теги:** пользовательские теги и AI-признак берутся из `filesProvider` непосредственно перед сохранением и передаются в чистую функцию `tagsAfterMetadataGeneration`, гарантируя сохранность правок, сделанных во время выполнения запроса.
5. **Изоляция инспектора:** поля UI и `editorialStateProvider` обновляются только если материал всё ещё открыт в инспекторе (`stillViewingTarget()`). Переключение на файл B оставляет инспектор B нетронутым при завершении операции A.

## Поведение при dispose

- Флаг `_isDisposed = true` выставляется в первой строке метода `dispose()`.
- Каждое возобновление после `await` (чтение EXIF, геокодинг, обращение к AI API, ожидание мьютекса диалога, запись в БД и файл) предваряется проверкой `if (!_isLive) return;`.
- Поздние ответы API или завершение фонового I/O после закрытия экрана не вызывают исключений, не обращаются к `ref`, `context`, `setState`, контроллерам и не запускают последующих звеньев цепочки (диалогов, сетевых запросов или записей).

## Ограничения и оставшиеся риски

- Не проверялись реальные платные запросы к API AI и нативный вызов `exiftool` в едином сквозном прогоне экрана на macOS с запущенным приложением (по правилам изолированных тестов).
- Сохранение ручных текстовых правок заголовка в инспекторе во время генерации не гарантируется полным версионированием черновиков (выходит за границы задачи и требует этапа устойчивых черновиков).
