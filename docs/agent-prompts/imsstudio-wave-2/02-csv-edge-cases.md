## Исправление 1 Все повторные цели исключаются

Сейчас подсчёт повторных id идёт после проверки значений, только по resolved. Ошибочная строка выпадает из подсчёта.

Пример при единственном photo.jpg в каталоге:

```csv
Filename,Title,IsEditorial
photo.jpg,first,true
photo.jpg,second,invalid
```

Ожидается: 0 применимых изменений. Обе строки нацелены на один материал, поэтому ни одна не должна победить.

Сначала однозначно сопоставь строки с материалами. Подсчитай цели по всем однозначно сопоставленным строкам независимо от корректности Title/IsEditorial/EditorialDate. Потом исключи все повторные цели и проверяй значения остальных.

Правило причин: для однозначно сопоставленного повторного id конфликт имеет приоритет; каждая такая строка получает одну запись проблемы duplicateTarget. Несопоставленные строки сохраняют свою причину. Не увеличивай число проблем двойным учётом одной строки. Не объединяй строки и не выбирай первую или последнюю.

Проверь повторы по имени, по Path и смесь этих способов. Не считай повтором одинаковое имя двух различных материалов, когда каждый однозначно указан своим Path.

## Исправление 2 Строгая дата

DateTime.tryParse допускает нормализацию. Сейчас 2026-02-31 превращается в 2026-03-03 без ошибки.

Поддержи явно ограниченный понятный набор ISO-значений:
- дата YYYY-MM-DD;
- дата и время YYYY-MM-DDTHH:mm:ss, необязательная дробная часть секунды от 1 до 6 цифр;
- для даты со временем необязательный Z либо смещение ±HH:mm; допустимо также ±HHmm для совместимости с разбором текущего формата;
- без часового пояса сохраняется существующая локальная интерпретация; Z и смещение задают тот же момент времени.

Экспорт приложения с DateTime.toIso8601String должен полностью импортироваться. Отдельную миграцию часовых поясов не делай. Внешние пробелы поля даты допускаются; пустая дата очищает значение.

До принятия результата проверяй календарную дату, включая високосный год, и границы времени: часы 00–23, минуты и секунды 00–59. Для смещения в поддержанном формате допускаются часы 00–23 и минуты 00–59; не разрешай нормализацию 99:99. Не сравнивай исходные локальные компоненты напрямую с UTC после применения смещения. Отсутствующая колонка сохраняет дату; неверная непустая дата исключает строку целиком с invalidDate, а не только поле даты.

Используй стандартные средства Dart и небольшой проверяемый код. Не добавляй зависимость ради парсинга. Поддержка всех альтернатив ISO-8601, неполных дат, недель и порядковых номеров дней в этой задаче не нужна.

## Исправление 3 Точный Path и сохранение текста

Для выбора режима сопоставления используй фактическое отсутствие/пустоту Path. Значение из пробелов является непустым неверным путём и не допускает fallback по Filename. Не выполняй trim самого пути при сопоставлении.

Проверь также _textValue и _optionalTextValue: сейчас trim().isEmpty превращает текст из пробелов в очистку. Согласованное правило — именно пустая ячейка очищает, непустое содержимое сохраняется буквально, включая пробелы и переносы строк. Исключения: заголовки колонок, boolean и дата имеют свои явно описанные правила нормализации.

Абсолютные пути с пробелом в конце компонента остаются точными строками. Относительный, неизвестный или неоднозначный Path остаётся проблемой. Непустой Path вместе с несовпадающим Filename не применяется.

## Исправление 4 Частичный успех обновляет каталог

Сейчас диалог вызывает DatabaseHelper.updateFile напрямую. Родитель обновляет filesProvider только после true. При частичном успехе и закрытии с false в базе уже есть изменения, а provider остаётся старым.

Исправь это внутри CsvImportPreviewDialog:
1. После фактически успешных записей обеспечь обновление filesProvider существующим механизмом. Не требуй изменений родительского экрана.
2. При нуле успешных записей и при отмене до начала не имитируй обновление данных.
3. При частичной ошибке диалог остаётся открытым, показывает выполненное/ошибки, возвращает false при «Закрыть». Это не должно скрывать уже успешные изменения.
4. Повторяет только неудачные записи; успешные не пишет заново.
5. true возвращается только после успешного применения всех допустимых записей.
6. Во время применения не допускай второго запуска и обычного закрытия диалога через Escape/назад. После ошибки закрытие доступно. Обработай mounted перед UI-действиями.
7. Не заменяй частичное применение транзакцией всей таблицы и не добавляй откат ранее успешных строк.
8. Тестовая persistFile не должна внезапно открывать настоящую пользовательскую базу. В тестах provider переопределяется или используется поддельный контейнер с контролируемой загрузкой.

Не меняй boolean-контракт на объект результата и не передавай false как «ничего не изменилось». Исправление обновляет наблюдаемый каталог; перестройка полей инспектора и общая система черновиков сюда не входят.
