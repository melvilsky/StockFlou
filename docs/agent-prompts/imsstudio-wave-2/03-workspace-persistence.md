## Результат для пользователя

Подключённая рабочая папка остаётся в списке после перезапуска, даже если внешний диск отключён или доступ временно отсутствует. Приложение показывает состояние и позволяет повторить проверку. Повторное подключение той же папки сохраняет её место в списке. Старые настройки переносятся без потери списка папок.

Это новый небольшой шаг этапов 0–1 общего плана. В этой задаче не нужно строить дерево каталогов, общий каталог материалов или систему доступа фоновых задач.

## Что происходит сейчас

WorkspacesNotifier._loadFromPrefs читает workspace_entries, либо старый workspace_paths, после чего проверяет существование каталогов. В state попадают только valid. Отключённый диск убирает запись из текущего списка; следующая запись настроек может закрепить потерю.

Старый workspace_paths удаляется до подтверждённого сохранения списка в workspace_entries. _loadFromPrefs вызывается асинхронно из build и может завершиться после пользовательского добавления папки. Есть нормализация, которая обрезает корневой "/" до пустой строки и в старом формате удаляет значимые пробелы пути.

В main.dart _buildWorkspacesBlock показывает только paths и currentIndex, без состояния доступности.

## Сохраняемые интерфейсы

Сохрани рабочими WorkspaceEntry(path, bookmark), его чтение/запись JSON, WorkspacesState.entries/paths/currentIndex/currentPath/currentEntry/copyWith, workspacesProvider, refreshWorkspaceProvider, addWorkspace, removeWorkspace, setCurrent, setCurrentByPath.

Можно добавить необязательные поля со значениями по умолчанию, отдельную карту состояния доступности по точному пути и метод повторной проверки. Не требуй правок существующих вызывающих функций GenerationScreen. Старый JSON с path/bookmark должен читаться без новой миграции базы.

Доступность — временное наблюдение, а не причина удалить WorkspaceEntry. Не сохраняй «доступен» как достоверное состояние на следующий запуск.

## Правила сохранения и загрузки

1. При старте сохраняй все корректно прочитанные непустые пути и их bookmarks, включая недоступные. Порядок сохраняется. Проверяй структуру каждого элемента отдельно: один неправильный элемент не должен скрывать все остальные.
2. Путь — точная строка. Не применяй trim к хранимым/сопоставляемым путям. Пустая строка недопустима. Конечные разделители можно нормализовать одинаково во всех методах, но "/" должен оставаться "/"; пробел в имени папки сохраняется. Не разрешай symlink и не меняй регистр.
3. Повторные одинаковые нормализованные пути не создают новую запись. Сохраняй первое место в списке и действующий bookmark; повторный выбор через системный диалог обновляет bookmark, если удалось получить новый.
4. Выбранная папка восстанавливается даже при недоступности. При удалении/исключении некорректной записи сохраняй выбранный путь, если он остался, а не полагайся только на старый числовой индекс. Отрицательный/слишком большой индекс обрабатывай безопасно; пустой список имеет currentPath == null.
5. Если используется старый workspace_paths, сначала запиши новый формат и текущий индекс, проверь успех, и только потом удаляй старый ключ. При ошибке чтения или записи не удаляй единственную исходную копию.
6. Если новый JSON повреждён, не перезаписывай его пустым значением автоматически. Дай понятный признак ошибки загрузки. Если доступен валидный старый формат, его можно использовать для восстановления; перед замещением повреждённого значения сохрани его резервную копию отдельным служебным ключом. При невозможности сохранить копию исходное значение не меняй. Не создавай бесконечную историю резервных копий.
7. Старый формат не должен вновь появиться после явного удаления всех папок: валидный пустой workspace_entries является полноценным сохранённым состоянием и имеет приоритет над legacy.
8. Инициализация не перезаписывает add/remove/setCurrent, выполненные во время загрузки. Используй простой порядок ожидания и сериализации мутаций. Поздняя проверка доступности удалённого пути не возвращает его в список.
9. Ошибки SharedPreferences не должны выглядеть как успешное долговременное сохранение. Не стирай исходные данные при ошибке; предоставь экрану понятную ошибку и возможность повторить. Учитывай как исключение, так и отрицательный результат записи там, где API возвращает bool.
10. После уничтожения provider нет запоздалой записи в его state и необработанных асинхронных ошибок.

## Проверка доступности и macOS

Достаточно состояний «Проверяется», «Доступна», «Недоступна» и понятного сообщения при сбое проверки. Не делай вывод «удалена навсегда» по одному exists == false.

Проверка выполняется при загрузке, после подключения/повторного подключения и по явному обновлению. Не добавляй постоянный таймер, filesystem watcher или сетевой монитор.

Для macOS используй уже установленный SecureBookmarks. Успешный startAccessingSecurityScopedResource должен иметь ровно один соответствующий stop в finally для этой краткой проверки. Не останавливай ресурс, если твоя проверка его не открыла. Ошибка resolve/start/probe/stop не удаляет запись.

Не считай Directory.exists полной проверкой возможности чтения: проверка доступности должна учитывать возможность прочитать каталог, не сканируя его содержимое целиком. На больших папках не собирай список всех файлов; достаточно успешного начала/завершения ограниченной попытки чтения с корректной отменой подписки.

Если bookmark разрешился в другой путь, не меняй автоматически пути материалов и не перепривязывай каталог к другой папке. Сохрани существующую запись и покажи необходимость повторного подключения. Полное «Указать новое расположение» будет отдельной задачей. Не требуй Full Disk Access и не меняй entitlements.

Эта краткая проверка НЕ заменяет общий менеджер разрешений для генерации, записи, превью и загрузки. Не удерживай все security scopes бессрочно ради этого задания и не объявляй решённой работу фоновых задач из нескольких корней.

## Изменения боковой панели

1. Папка остаётся видимой независимо от состояния. Название и полный путь доступны, длинный путь не ломает ширину панели. Для "/" покажи понятное имя, а не пустой текст.
2. Рядом с недоступной папкой показывай значок и понятный текст/tooltip «Папка недоступна. Подключите диск или выберите эту папку снова». Не различай отсутствие разрешения и отключение диска без надёжного основания.
3. Состояние не передаётся одним цветом; элементы доступны с клавиатуры и имеют подписи.
4. Кнопка «Обновить» повторно проверяет доступность выбранной папки, затем использует существующий refreshWorkspaceProvider для обновления содержимого. Не меняй контракт этого provider. Ошибка показывается понятным сообщением.
5. «Добавить папку» использует существующий системный выбор. Выбор того же пути обновляет существующую запись/bookmark без дубля. Ошибки добавления и сохранения видны пользователю.
6. Удаление из списка остаётся явным действием пользователя и удаляет только рабочую область из настроек. Не удаляй файлы, каталог AppFile или метаданные.
7. Остальные блоки MainShell и маршруты приложения не перестраивай. Пока выбранная папка недоступна, её состояние объясняет боковая панель; полный экран восстановления — за пределами этой задачи.

## Обязательные тесты

Используй mock SharedPreferences/внедряемые зависимости и временные каталоги. Для bookmarks — контролируемые подделки; не используй пользовательские разрешения.

- Два сохранённых пути, один недоступен: после загрузки оба на месте, выбранный недоступный путь сохранён.
- Изменение текущей папки и перезагрузка не теряют недоступный путь.
- Диск «возвращается»: повторная проверка меняет состояние, не добавляет дубль и не меняет порядок.
- Старый формат корректно переносится; новый записан раньше удаления старого. Проверь провал записи и удаления отдельно.
- Пустой валидный новый список не восстанавливается из устаревшего legacy.
- Повреждённый JSON не уничтожается; валидные элементы смешанного массива сохраняются.
- Отрицательный/выходящий за пределы индекс безопасен; исключение некорректного элемента перед выбранным не выбирает другую папку.
- Путь "/" и путь с конечным пробелом сохраняются; "/tmp/folder/" и "/tmp/folder" не дают две записи.
- add/remove/setCurrent во время задержанной загрузки не теряются. Поздний результат проверки удалённой папки не возвращает её.
- Ошибка resolve/start/probe/stop не удаляет workspace; успешные start/stop сбалансированы, неуспешный start не вызывает stop.
- Dispose до окончания проверки не вызывает ошибку состояния.
- Widget-тест боковой панели: недоступная папка видна; повтор проверки доступен; повторное подключение не создаёт дубль; удаление не вызывает операций над файлами.
- Узкая панель, длинное имя, светлая/тёмная темы и клавиатурный фокус.

Не обещай, что подделка bookmark доказывает работу системного диалога macOS. Если ручную проверку не выполнял, прямо отметь это в отчёте.

Запусти flutter test test/workspaces_persistence и flutter analyze --no-pub. Не меняй реальные SharedPreferences пользователя и не отключай диски ради теста.
