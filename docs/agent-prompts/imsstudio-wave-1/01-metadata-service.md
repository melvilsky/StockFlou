## Что уже известно

MetadataService.writeMetadata сейчас является статическим методом и возвращает Future<bool>. Он принимает filePath, title, keywords и необязательный description. Запись выполняется через Process.run('exiftool', args). При description == null или пустой строке описание сейчас вообще не записывается, поэтому явная очистка не работает.

Также существуют readExifLocationAndDate и isExiftoolAvailable. Их сигнатуры и существующее поведение необходимо сохранить.

## Совместимость и новые интерфейсы

1. Сохрани существующий writeMetadata с теми же обязательными параметрами и возвращаемым Future<bool>. Сделай его совместимой обёрткой над расширенной записью.
2. Добавь writeMetadataDetailed с теми же входными полями и результатом FileMetadataWriteResult:

Если небольшое изменение названия требуется существующими соглашениями проекта, сохрани описанную семантику и укажи точный интерфейс в отчёте.

## Требуемое поведение записи

- title и keywords означают значения для записи, включая пустые значения.
- description == null означает «не менять описание в файле».
- description == '' означает «очистить описание». Должны очищаться те же поля, куда сервис записывает непустое описание.
- Непустое описание записывается целиком, включая переносы строк и Unicode.
- Список ключей по текущему строковому интерфейсу разбирается по запятым, с удалением внешних пробелов и пустых элементов. Порядок и многословные фразы сохраняются. Новую семантику разделителей не вводить.
- Ненулевой код завершения, невозможность запустить ExifTool и ошибки доступа дают success == false. Совместимый writeMetadata возвращает false.
- Предупреждение в stderr само по себе при exitCode == 0 не превращает успешную запись в ошибку.
- В сообщении об ошибке сохраняется понятная причина. Не выводи полное содержимое метаданных в логи.
- Путь не обрезается через trim(): пробелы могут быть частью имени. Аргументы передаются отдельным списком, без shell-команды и конкатенации командной строки.
- Используй существующий набор записываемых IPTC/XMP/EXIF-полей. Не очищай все метатеги и не трогай GPS, дату съёмки или прочие поля.
- Не добавляй широкую обработку неизвестных форматов. Сервис работает в пределах существующих возможностей ExifTool; каталог поддержки форматов здесь не реализуется.

## Требуемое поведение чтения

- Прочитай только основные поля названия, описания и ключей, используя JSON-вывод ExifTool.
- Различай группы тегов. Для одного смыслового поля предпочитай непустое XMP-значение, затем соответствующее IPTC, затем EXIF, если у этого поля есть поддерживаемый эквивалент.
- Если есть несколько наборов ключей, выбери один по этому приоритету; не склеивай наборы и не меняй порядок.
- Ключи, возвращённые массивом, сохраняй отдельными элементами; многословная фраза остаётся одним элементом. Одиночное строковое значение становится одним элементом.
- Успешно прочитанный объект без основных метаданных: success == true, title/description == null, keywords пуст.
- Повреждённый JSON, неожиданный тип корневого значения, пустой список вместо результата для указанного файла и сообщённая ExifTool ошибка: success == false.
- Перед реализацией уточни точные названия групп и форму JSON по локальному ExifTool или его официальной документации. Не угадывай названия полей.
- readMetadata ничего не записывает на диск и не обновляет БД.

## Обязательные тесты

Через подставной запуск процесса проверить:
- XMP-приоритет и переход к IPTC/EXIF при отсутствии значения.
- Массив ключей, одиночный ключ, пустые метаданные.
- Повреждённый JSON и ошибка запуска.
- Ненулевой exitCode, а также exitCode == 0 с предупреждением.
- description == null не включает аргументы изменения описания.
- description == '' включает очистку всех используемых полей описания.
- Непустое описание, Unicode, кавычки, перенос строки.
- Путь с пробелами и специальными символами остаётся одним аргументом без изменения.
- Порядок ключевых фраз сохраняется.
- Старый writeMetadata возвращает bool, соответствующий подробному результату.

Дополнительно, только если ExifTool уже установлен: создать временный JPEG средствами имеющейся зависимости image, записать название/описание/ключи, прочитать обратно, очистить описание и проверить повторным чтением. Удалять можно только собственные временные файлы. Отсутствие ExifTool не мешает обязательным тестам с подстановкой.

Команды: flutter test test/metadata_service/ и flutter analyze для изменённых файлов.

## Критерий готовности

Сервис корректно читает и записывает основные метаданные, поддерживает явную очистку и сообщает ошибку без нарушения старых вызовов. В отчёте прямо укажи: основной экран пока не переведён на подробные результаты, поэтому вся проблема сообщений «сохранено» этой задачей не закрывается.
