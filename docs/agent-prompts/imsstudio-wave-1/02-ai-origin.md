## Цель

Исправить конкретную ошибку: генерация названия, описания и ключевых слов не должна автоматически ставить метку «материал создан ИИ».

AppTags.aiGenerated относится к происхождению изображения/видео. Ручной AI-переключатель продолжает управлять этим признаком. Эта задача не вводит систему черновиков и не переписывает весь процесс генерации.

## Твоя зона изменений

Разрешено менять:
- lib/features/generation/presentation/generation_screen.dart

Разрешено создать:
- lib/features/generation/domain/generation_tags.dart
- test/generation_ai_origin/generation_tags_test.dart
- дополнительные тесты только внутри test/generation_ai_origin/

Не меняй AppFile/AppTags, editorial_state_provider.dart, generation_editorial_section.dart, сетевой клиент, MetadataService, CSV-сервис, видеоплеер, БД и общую навигацию.

В generation_screen.dart меняй только подготовку и применение результата одиночной/пакетной генерации, необходимую для этой задачи. Не форматируй и не перестраивай весь большой экран без необходимости.

## Что уже известно

В _generateAI и _generateBatchAI копируются теги материала, после чего безусловно добавляется AppTags.aiGenerated. В ручном редакторе уже существует отдельный способ включить и выключить AI-метку.

При одиночной генерации некоторые данные берутся из _selectedExistingFile после асинхронного запроса. Нужно убедиться, что результат и теги относятся к исходному обрабатываемому материалу, а не к файлу, выбранному позднее.

## Точное поведение

1. У материала без ai_generated после успешной генерации этой метки по-прежнему нет.
2. У материала с ранее установленной ai_generated после генерации метка сохраняется.
3. Если пользователь вручную изменил AI-признак, пока запрос выполнялся, при применении результата используй актуальные теги именно обрабатываемого материала. Не восстанавливай старое значение из снимка.
4. Другие пользовательские теги сохраняются.
5. Существующее добавление/удаление editorial по действующему режиму генерации сохраняется. Не используй значение AI-переключателя активного инспектора как общее значение для всей выборки.
6. В пакетной генерации теги рассчитываются отдельно для каждого файла: серия может одновременно содержать обычные фотографии и созданные ИИ изображения.
7. Новому локальному материалу без существующей записи не добавляй AI-признак. Если к моменту применения результата запись уже создана ручным действием, используй её идентификатор и текущие теги.
8. Старые AI-метки в базе массово не очищать: их происхождение неизвестно. Миграцию проверки старых меток эта задача не реализует.
9. В этой задаче не меняй правила readyToUpload, прямой записи метаданных в оригиналы, CSV или очереди. Эти изменения требуют отдельной согласованной работы. Не сообщай, что весь этап 0 выполнен.

## Как реализовать

1. Прочитай обе функции генерации целиком и найди все места, где в этих потоках устанавливается aiGenerated либо вызывается setAI(true).
2. Удали автоматическое добавление AI-признака по факту генерации текста.
3. Вынеси общий расчёт тегов обеих веток в маленькую чистую функцию в generation_tags.dart:
   List<String> tagsAfterMetadataGeneration({
     required List<String> currentTags,
     required bool isEditorial,
   })
   Она копирует входной список, сохраняет ai_generated и пользовательские теги, добавляет editorial при isEditorial == true и удаляет editorial при false. Входной список не мутирует. Никакого Riverpod/БД/сети в этой функции.
4. Используй эту функцию в обеих реальных ветках генерации; не создавай тестируемый helper, который не вызывается приложением.
5. Для одиночной генерации до первого await зафиксируй целевой путь и, если есть, идентификатор. После получения ответа ищи актуальную запись по этому идентификатору/точному пути. Не используй текущую выделенную запись другого файла.
6. Для пакетной генерации перед сохранением каждого результата получай текущие теги соответствующего материала из filesProvider, а не из общего состояния инспектора и не только из начального снимка.
7. Обновляй поля инспектора только если пользователь всё ещё смотрит материал, для которого пришёл ответ. Сохранение результата в каталог относится к исходной цели.
8. Не начинай более широкий рефакторинг async-жизненного цикла. Обнаруженные независимые проблемы перечисли в отчёте.

## Обязательные тесты

На реально используемую чистую функцию:
- пустой список без Editorial остаётся пустым;
- обычные пользовательские теги сохраняются, ai_generated не появляется;
- существующая ai_generated сохраняется;
- включение Editorial добавляет только editorial;
- выключение Editorial удаляет только editorial;
- входной список после вызова не меняется;
- два материала с разным AI-признаком получают независимые результаты;
- повторное применение не добавляет повторный editorial.

Для асинхронной привязки проверь обе функции через чтение текущего diff и, если существующие тестовые точки позволяют, отдельный тест с отложенным ответом. Не добавляй зависимости и не запускай реальный AI-запрос ради теста. В отчёте отличай выполненный автоматический тест от сценария, проверенного только по коду.

Команды: flutter test test/generation_ai_origin/ и flutter analyze для изменённых файлов.

## Критерий готовности

Обе ветки используют общее правило: генерация текста не определяет происхождение медиа. Теги сохраняются для правильного файла, ручной AI-признак не подменяется значением другого материала, прежние метки не стираются массово.
