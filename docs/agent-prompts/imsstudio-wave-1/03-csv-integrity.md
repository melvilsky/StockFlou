## Цель

Исправить базовый CSV-обмен: описание должно переживать экспорт и импорт; одинаковые имена в разных папках не должны приводить к изменению случайного материала; отсутствующая колонка не должна очищать существующее поле.

Это ограниченная часть этапа 6 и исправление сохранности данных из этапа 0. Конструктор профилей площадок, новые режимы массового редактирования и полный каталог черновиков сюда не входят.

## Что уже известно

CsvMetadataService экспортирует Filename, Title, Keywords, IsEditorial, EditorialCity, EditorialCountry, EditorialDate. Description отсутствует.

Диалог импорта сейчас выбирает первое совпадение имени файла, не переносит описание, может менять отсутствующие в CSV Editorial-поля и вызывает запись в оригинал, не проверяя её результат.

Вызывающий экран использует:
- exportToCsv(List<AppFile>) → String;
- exportToFile(List<AppFile>, String) → Future<void>;
- importFromFile(String) → Future<List<Map<String, String>>>;
- CsvImportPreviewDialog(parsedData: ..., dbFiles: ...);
- результат диалога true/false.

Эти вызовы должны остаться совместимыми.

## Контракт CSV

1. Первые семь колонок и их порядок сохраняются. В конец добавь Description и Path.
2. Path содержит текущий полный путь материала. Это общий обменный CSV StockFlow; не выдавай его за профиль конкретного стока.
3. UTF-8, запятая как разделитель колонок, корректные кавычки, запятые внутри значений, CRLF/LF и переносы строк внутри полей.
4. Не преобразовывай строки в числа автоматически: ведущие нули в именах/тексте должны сохраняться.
5. Удаляй UTF-8 BOM только в начале документа. Можно убрать внешние пробелы заголовков. Содержимое текстовых полей, имена файлов и пути не обрезай автоматически.
6. Старый CSV без Description и Path должен импортироваться.
7. Пустой файл и файл только с заголовком дают пустой список данных. Полностью пустые строки пропускаются.
8. Пустые/повторяющиеся заголовки, отсутствие Filename, нарушенная структура CSV и строки с неправильным числом колонок должны давать понятную ошибку. Нельзя молча сдвигать или терять значения.
9. Неизвестные колонки допустимы и сохраняются в разобранных картах, но не влияют на AppFile.

## Однозначное сопоставление

Вынеси расчёт соответствий и будущих значений в чистую операцию CsvMetadataService.buildImportPlan(rows, files). Результат определи в csv_import_plan.dart: список изменений и список проблем с номером CSV-записи, причиной и именем/путём. Номер записи считается с учётом заголовка; перенос внутри кавычек не создаёт новую запись.

Правила:
- Если непустой Path указан, ищи точное соответствие текущему path в переданном списке AppFile. Не ищи файл на диске, не открывай его и не создавай новую запись.
- Относительный Path, отсутствие точного совпадения или несколько записей с таким путём — проблема строки; не переходи автоматически к поиску по имени.
- При совпавшем Path колонка Filename должна соответствовать имени найденного материала; иначе строка требует исправления.
- Если Path отсутствует или пуст, сопоставляй по точному Filename только при единственном совпадении.
- Ноль совпадений — «Файл не найден в каталоге»; несколько — «Неоднозначное имя, укажите Path».
- Если несколько строк CSV нацелены на один материал, исключи все такие строки из применения и покажи конфликт. Последняя строка не должна молча побеждать.
- Однозначные строки можно применить после предпросмотра; проблемные пропускаются. В первой версии ручной выбор совпадения в диалоге не нужен: пользователь исправляет Path в CSV.

## Применение значений

- Если колонка отсутствует, соответствующее существующее значение остаётся без изменений.
- Пустая присутствующая Title/Description/Keywords/EditorialCity/EditorialCountry намеренно очищает поле. Для основных текстов используй пустую строку; для необязательных Editorial-значений допускается null по существующей модели.
- Присутствующая IsEditorial принимает только true/false без учёта регистра и с допустимыми внешними пробелами. Иное значение, включая пустое, делает строку ошибочной.
- EditorialDate принимает ISO-8601; пустое значение очищает дату, непустая неразбираемая дата делает строку ошибочной.
- Если IsEditorial отсутствует, сохраняй одновременно isEditorial и editorial-тег. Если присутствует, согласованно обнови оба. AI-признак и пользовательские теги не менять.
- Используй существующий copyWith: в AppFile уже различаются непереданное nullable-поле и явно переданный null.
- Сохраняй id, path, filename, createdAt и существующий workflowStatus. Не выставляй readyToUpload по факту импорта. Полная переоценка готовности и отдельное состояние черновика будут интегрированы позже.

## Поведение диалога

- Предпросмотр показывает количество записей, однозначных изменений и проблем, а также список причин пропуска в ограниченной по высоте прокручиваемой области.
- До подтверждения не обновляй БД.
- Явно напиши: «Импорт изменит метаданные в каталоге. Оригинальные файлы не изменяются».
- При подтверждении обновляй каталог существующим DatabaseHelper.updateFile; убери вызовы MetadataService.writeMetadata из этого сценария.
- Если применить нечего, кнопка импорта неактивна.
- При частичной ошибке БД не закрывай диалог с true. Покажи выполненное и ошибки; повтор применяет только неудачные изменения. Пользователь может закрыть диалог после просмотра результата.
- true возвращается только когда все выбранные однозначные изменения успешно применены. Пропущенные проблемные строки заранее явно показаны пользователю.
- Сохрани существующий обязательный конструктор. Для widget-теста допускается необязательный обработчик persistFile(AppFile), по умолчанию вызывающий настоящий DatabaseHelper; так тест не использует пользовательскую БД.
- Не представляй этот локальный импорт как полностью реализованную систему устойчивых черновиков: это отдельная следующая интеграция.

## Обязательные тесты

- Экспорт содержит прежние семь колонок и новые Description/Path в конце.
- Полный цикл экспорт → разбор → план импорта сохраняет название, описание, ключи и Editorial-значения.
- Кавычки, запятые, Unicode, многострочное описание, CRLF/LF, BOM и ведущие нули.
- Старый CSV без новых колонок.
- Отсутствующая колонка сохраняет поле; присутствующая пустая очищает его.
- Два файла с одинаковым именем: без Path оба не меняются; с точным Path меняется один.
- Неизвестный Path не приводит к поиску первого совпавшего имени.
- Повторные строки одного материала не применяются.
- Неверные дата/boolean и структура дают явные ошибки.
- До подтверждения persistFile не вызывается; после подтверждения вызывается только для однозначных строк.
- Частичная ошибка не возвращает true, повтор не применяет успешные строки ещё раз.
- Импорт не вызывает ExifTool и не меняет оригинальные медиа.

Команды: flutter test test/csv_metadata/ и flutter analyze для изменённых файлов.

## Критерий готовности

Описание не теряется при обмене; импорт не выбирает случайный файл, не стирает отсутствующие поля и не пишет в оригиналы. Старые вызовы сервиса и диалога продолжают работать без изменения основного экрана.
