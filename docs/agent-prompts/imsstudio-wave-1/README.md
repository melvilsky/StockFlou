# Первая параллельная группа задач StockFlow

Дата подготовки: 22 октября 2026 года.

Подготовлены четыре самостоятельных промпта. Они выделены из обновлённого плана и могут выполняться одновременно. Это задания для будущего запуска; при подготовке пакета агенты не запускались, приложение не изменялось.

## Промпты

| Агент | Промпт | Результат | Производственные файлы в его владении |
|---|---|---|---|
| 1 | [Метаданные](01-metadata-service.md) | Чтение существующих метаданных, явная очистка описания, подробный результат записи при совместимости старых вызовов | metadata_service.dart; новый file_metadata_result.dart |
| 2 | [Происхождение AI](02-ai-origin.md) | Генерация текста сохраняет реальный AI-признак конкретного материала | generation_screen.dart; новый generation_tags.dart |
| 3 | [CSV](03-csv-integrity.md) | Описание не теряется, неоднозначные строки не применяются, импорт меняет только каталог | csv_metadata_service.dart; csv_import_preview_dialog.dart; новый csv_import_plan.dart |
| 4 | [Видеопревью](04-video-preview.md) | Видимая ошибка, повтор, тайм-аут и корректная смена контроллеров | video_player_widget.dart |

Полные пути, входные и выходные интерфейсы, проверки и ограничения находятся в каждом промпте. Каждый файл можно целиком скопировать отдельному агенту: повторяющиеся общие правила включены намеренно.

## Как запускать

1. Выдай каждому агенту только его промпт.
2. Предпочтительны отдельные рабочие копии одной и той же текущей версии проекта. Не начинай от старой default-ветки, если исследованная версия существует только в текущем checkout.
3. Если используешь один каталог, соблюдай владение файлами из промптов. Никто не переключает ветку, не меняет зависимости, не форматирует весь проект и не запускает общий рефакторинг.
4. В отдельных копиях приложи эти документы, если они ещё не входят в базовую версию Git. Сам промпт содержит достаточную постановку и не требует результатов другого агента.
5. Адресные тесты можно выполнять независимо. В одном checkout Flutter-команды могут ожидать общий служебный lock; это не повод удалять lock-файлы. Общий тестовый прогон выполняется один раз после объединения.
6. Не поручай в это же время другим агентам изменения указанных файлов. Особенно generation_screen.dart целиком закреплён за агентом 2.

Никому из четырёх агентов не требуется создавать миграции, менять общие модели AppFile/WorkflowStatus или ждать новый API другого задания.

## Почему эти задачи независимы

- Агент 1 сохраняет совместимый writeMetadata и добавляет новые интерфейсы; остальные агенты на них не переходят.
- Агент 2 исправляет применение AI-признака только в генерации.
- Агент 3 сохраняет старые вызовы CSV и конструктор диалога, а запись в оригиналы из импорта удаляет; его тесты не зависят от ExifTool.
- Агент 4 сохраняет текущий конструктор видеовиджета, добавляя только необязательную тестовую точку.
- У всех разные папки тестов; никто не меняет общий тестовый файл или зависимости.

## Как принять результаты

1. Проверить, что каждый агент менял только свою зону и не затронул чужой исходный diff.
2. Проверить, что tests используют реальные новые ветки приложения, а не отдельную имитацию логики.
3. Объединить изменения; фиксированного порядка между этими четырьмя задачами нет при соблюдении контрактов.
4. Выполнить четыре адресных группы тестов, затем общий flutter test и flutter analyze. Отделить существовавшие ранее проблемы от появившихся.
5. Проверить реальные запись/чтение временного JPEG при наличии ExifTool и воспроизведение временного видео на macOS. Не использовать пользовательские оригиналы.
6. Проверить вручную, что CSV-импорт явно сообщает об изменении каталога и не записывает медиа, а отсутствие Description в старом CSV сохраняет существующее описание.
7. Не объявлять весь этап 0 завершённым по результатам этой группы.

## Что остаётся последовательной работой

Следующая согласованная задача должна определить единый каталог, устойчивые черновики, версию метаданных, состояние записи и проверку готовности. Затем потребуется подключить новые результаты MetadataService к основному редактору, согласовать поведение генерации и CSV с общим управлением черновиками и не помечать сохранение автоматически как готовность к отправке.

Полная миграция старых AI-меток, общая отмена операций и гарантии восстановления данных пока не реализуются.

Дерево папок, коллекции, физическое перемещение и очередь загрузки не выдаются слабым моделям одновременно до определения общих контрактов каталога. Их зависимости существенно теснее.
