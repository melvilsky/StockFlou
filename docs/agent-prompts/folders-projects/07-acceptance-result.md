## 2. Обнаруженные дефекты (P1 и P2) с точными местами и шагами воспроизведения

### Дефект 1 (P1): Локальные файлы с диска без `AppFile` не отображаются в проектах
- **Точное место:** `lib/features/generation/presentation/generation_screen.dart:2419–2429`, `lib/features/generation/presentation/generation_screen.dart:2154–2159`.
- **Суть проблемы:**
  В коде построения сетки `GenerationScreen` список локальных файлов `currentLocalFiles` явно принудительно обнуляется, если тип области не `folder` и не `all`:
  ```dart
  final currentLocalFiles =
      (scope.type == SearchScopeType.folder ||
              scope.type == SearchScopeType.all)
          ? _localFiles.where(...).toList()
          : <File>[];
  ```
  Кроме того, при переключении на проект (`ref.listen(organizationSearchSettingsProvider)` на строке 2154) метод сканирования папок `_loadCurrentWorkspaceFiles` не вызывается для папок проекта. В результате файлы, присутствующие на диске в папках проекта, но еще не открывавшиеся в инспекторе/не внесенные в SQLite, в проекте отсутствуют.
- **Шаги воспроизведения:**
  1. Создать проект и привязать к нему папку с файлами `photo1.jpg`, `photo2.jpg`, которые еще не были проиндексированы в базе данных.
  2. Выбрать проект в организационном сайдбаре.
  3. **Ожидалось:** сетка проекта отображает файлы папок проекта (каталогизированные + локальные некаталогизированные).
  4. **Фактически:** сетка проекта пуста («В этом проекте пока нет файлов»).
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 1»).

### Дефект 2 (P1): Поиск по метаданным (Title, Keywords, Description) и фильтры из задачи 05 не действуют на сетку
- **Точное место:** `lib/features/generation/presentation/generation_screen.dart:564–577`, `lib/features/generation/presentation/generation_screen.dart:2368–2438`.
- **Суть проблемы:**
  В задаче 05 был разработан поисковый движок `SearchEngine` с поддержкой поиска по 4 мета-полям (`filename`, `metadataTitle`, `metadataKeywords`, `metadataDescription`) и развитой фильтрацией (`SearchFilterCriteria`).
  Однако в `GenerationScreen`:
  1. Строка 2370: читается только `searchSettings.scope`, а `searchSettings.filters` и `organizationSearchResultsProvider` полностью игнорируются;
  2. Фильтрация сетки выполняется приватным методом `_applyFilters` (строки 564–577), где поиск осуществляется исключительно по совпадению с именем файла:
     ```dart
     filteredDb = filteredDb.where((f) => f.filename.toLowerCase().contains(q)).toList();
     ```
  3. Поля `metadataKeywords`, `metadataTitle`, `metadataDescription`, а также фильтры `hasKeywords`, `workflowStatuses`, `isEditorial` в сетке не участвуют.
- **Шаги воспроизведения:**
  1. Добавить файл `sunset.jpg` с ключевыми словами `"golden_hour, landscape"`.
  2. Ввести в поле поиска верхней панели `"golden_hour"` или установить фильтр в `organizationSearchSettingsProvider`.
  3. **Ожидалось:** файл `sunset.jpg` отображается в сетке.
  4. **Фактически:** файл `sunset.jpg` скрывается, так как его имя не содержит подстроку `"golden_hour"`.
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 3»).

### Дефект 3 (P1): Отсутствие восстановления настроек поиска, области и скролла после перезапуска приложения
- **Точное место:** `lib/main.dart:185–215`, `lib/features/generation/presentation/generation_screen.dart:200–207`, `lib/features/organization_search/application/organization_search_providers.dart:126–140`.
- **Суть проблемы:**
  В модуле 05 созданы методы `persist()` и `restore()` в `OrganizationSearchSettingsNotifier`. Однако ни при инициализации `main.dart`, ни в `initState` экрана `GenerationScreen` метод `restore()` не вызывается. При переключениях источников и фильтров метод `persist()` также не вызывается. Кроме того, параметр `scrollOffset` никак не привязан к `ScrollController` сетки файлов.
- **Шаги воспроизведения:**

  3. **Ожидалось:** восстанавливается последний активный источник (проект/коллекция), применённые фильтры и позиция скролла.
  4. **Фактически:** восстанавливается дефолтное состояние `SearchScope.all()`, фильтры пусты, скролл сброшен на 0.
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 4»).

### Дефект 4 (P1): Исчезновение offline-файлов из сетки коллекций и проектов при отключении диска
- **Точное место:** `lib/features/generation/presentation/generation_screen.dart:2357`, `lib/core/state/files_provider.dart:8–23`.
- **Суть проблемы:**
  Сетка в `GenerationScreen` слушает `filesProvider`:
  ```dart
  final filesState = ref.watch(filesProvider);
  ```
  В `files_provider.dart` метод `build()` вызывает `_filterExistingFiles`, который проверяет `await File(file.path).exists()` и отсекает все файлы, находящиеся на отключенном носителе.
  В задаче 05 для сохранения видимости оффлайн-материалов был специально введен `allCatalogFilesProvider`, который читает полный каталог из SQLite. Но `GenerationScreen` использует `filesProvider`. В результате при отключении внешнего диска все оффлайн-файлы коллекций бесследно исчезают из интерфейса сетки вместо показа с бейджем оффлайн-доступности.
- **Шаги воспроизведения:**
  1. Добавить файлы с внешнего диска в коллекцию «Избранное».
  2. Отключить внешний диск.
  3. Открыть коллекцию «Избранное».
  4. **Ожидалось:** файлы коллекции видны в сетке со статусом `isAccessible: false` (или бейджем недоступности).
  5. **Фактически:** коллекция отображается пустой.
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 5»).

### Дефект 5 (P2): Режим «С подпапками» (`includeSubfolders`) не сканирует локальные файлы подпапок
- **Точное место:** `lib/features/generation/presentation/generation_screen.dart:700–702`.
- **Суть проблемы:**
  Сканирование папки в `_loadCurrentWorkspaceFiles` жестко использует плоский список `dir.list(recursive: false)`:
  ```dart
  final List<FileSystemEntity> entities = await dir.list(recursive: false).toList();
  ```
  При включении переключателя «С подпапками» в дереве навигации подпапки сканируются только для файлов, уже внесённых в БД SQLite (`_resolveScopeDbFiles`). Файлы на диске во вложенных подпапках, не внесенные в базу, не попадают в `_localFiles` и не отображаются.
- **Шаги воспроизведения:**
  1. Создать папку `Root`, внутри создать подпапку `Sub`, в которую поместить новый файл `nested.jpg`.
  2. Открыть папку `Root` в приложении и включить переключатель «С подпапками».
  3. **Ожидалось:** файл `nested.jpg` появляется в сетке среди локальных файлов.
  4. **Фактически:** файл `nested.jpg` отсутствует в сетке.
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 2»).

### Дефект 6 (P2): Сброс восстановленной подпапки при монтировании дерева навигации в `main.dart`
- **Точное место:** `lib/main.dart:365–381`.
- **Суть проблемы:**
  В `main.dart` callback `onSelection` от `FolderNavigationView` содержит защиту:
  ```dart
  if (searchSettings.scope.type != SearchScopeType.folder &&
      selection.path == currentPath &&
      !selection.includeSubfolders) {
    return;
  }
  ```
  Если текущей областью была восстановленная подпапка (например, `/Root/Subfolder`), тип области равен `SearchScopeType.folder`. Условие `!= SearchScopeType.folder` дает `false`, и начальное событие `open()` от дерева папок (сообщающее корневой путь `/Root`) перезаписывает выбор подпапки обратно на корень.
- **Шаги воспроизведения:**
  1. Выбрать в дереве подпапку `/Root/Subfolder`.
  2. Перезагрузить компонент дерева (или переоткрыть экран).
  3. **Ожидалось:** активным источником остаётся `/Root/Subfolder`.
  4. **Фактически:** источник сбрасывается на `/Root`.
- **Подтверждающий тест:** `test/folders_projects_acceptance/grid_search_link_acceptance_test.dart` (Группа «Проверка 6»).

## 6. Публичные контракты и рекомендации для задач устранения дефектов

1. **Сетка должна использовать `allCatalogFilesProvider` или `organizationSearchResultsProvider`:**
   Вместо прямого `ref.watch(filesProvider)` в `GenerationScreen:2357`, для поддержки оффлайн-файлов и полноценного поиска по метаданным сетка должна опираться на `organizationSearchResultsProvider` или `allCatalogFilesProvider`.
2. **Сканирование некаталогизированных файлов в проектах:**
   В `_loadCurrentWorkspaceFiles` при активном проекте необходимо инициировать сканирование всех связанных папок `projectFoldersProvider(projectId)` с поддержкой `recursive: true` при включенном `includeSubfolders`.
3. **Подключение персистентности настроек поиска:**
   В `main.dart` или `GenerationScreen.initState` добавить вызов `ref.read(organizationSearchSettingsProvider.notifier).restore()`, а при смене `scope`/`filters` — асинхронный вызов `persist()`.
4. **Уточнение guard в `main.dart:370`:**
   Проверять не только `scope.type != SearchScopeType.folder`, но и сохранение выбранного подпути внутри текущего корня (`scope.folderPath != selection.path`).
